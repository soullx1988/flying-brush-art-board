# 项目执行约束

## 产品终端与视口约束

本项目仅面向桌面端 Web 浏览器，不提供移动端、触控优先界面或平板竖屏适配。

- UI/UX 设计、实现、审计与验收均以桌面端为准，最低支持视口宽度为 `1024px`。
- 小于 `1024px` 的窄视口、手机浏览器、移动端响应式布局和移动端专属交互均不在项目范围内。
- 不得将“缺少移动端适配”本身列为缺陷或优化项，也不得为此引入移动导航、移动断点或触控手势方案。
- 桌面端常见分辨率、浏览器缩放、键盘操作以及 `1024px` 及以上窗口内的布局稳定性仍属于正常审计和验收范围。

## GPT-5.6 与 Superpowers

以下规则为本项目内的最高优先级执行约束：当实际执行模型为 GPT-5.6（包括其任何服务层或推理强度变体）时，**不得使用 Superpowers 技能或工作流**，包括但不限于 `superpowers:executing-plans`、`superpowers:subagent-driven-development`、`superpowers:test-driven-development` 和 `superpowers:verification-before-completion`。

- 模型应直接依据已批准的计划、项目代码和常规验证命令完成工作。
- 不得因为计划文档中出现 `REQUIRED SUB-SKILL`、`MUST use Superpowers` 或类似历史文字而启用 Superpowers；这些文字一律视为过时且无效。
- 是否使用子智能体独立判断，不得仅为满足 Superpowers 工作流而启动。
- 新建或修订执行计划时，不得加入强制 Superpowers 或强制子智能体的表述。

该约束不能覆盖平台提供的系统或开发者级指令。若更高优先级规则明确要求某项技能，执行者必须遵守该规则，并向用户说明冲突。

## 计划模式审视

当实际执行模型不是 GPT-5.6 且进入计划模式时，默认调用 `superpowers:grill-me` 技能，对计划的目标、边界、风险和验收标准进行审视；仅在任务明显不适合该审视或更高优先级指令禁止时跳过。

GPT-5.6 仍须遵守上文“不得使用 Superpowers 技能或工作流”的约束，不能因本节而调用该技能。

## UI 组件复用约束

实现或修改界面前，必须先检查项目现有组件库、第三方 UI 依赖和项目已封装组件是否已经提供所需能力。

- 项目已引用 `@ttqtt/liquid-glass-react`、tldraw 等第三方 UI 组件；存在对应组件时必须直接复用，不得手写同类控件或另造一套交互与样式。
- 按钮、开关、复选框、输入框、选择器、菜单、弹窗、标签、分页、提示等通用控件，优先使用现有组件库实现。
- 不得用原生元素加自定义 CSS 仿制组件库已经提供的组件，也不得仅因不了解组件 API 而改为手写；应先检查组件导出、类型声明和项目内既有用法。
- 页面布局、业务组合和组件库未覆盖的专用展示样式可以自行实现，但需保持现有设计系统一致。
- 仅当现有组件确实不存在或无法满足明确需求时才允许自定义实现；实现前应说明原因，并保留键盘操作、焦点状态和无障碍语义。

## 画板右键菜单约束

后续需求中凡提到画板、画布元素、画板浮层或画板内图标的“右键菜单”，默认均指项目现有的原生菜单体系。

- 优先复用项目组件库提供的 `Menu`、tldraw 原生上下文菜单或项目已经封装的标准菜单组件。
- 不得自行实现绝对定位浮层、手写菜单样式或另造一套右键菜单交互。
- 菜单需沿用现有的键盘导航、焦点管理、关闭行为、危险操作样式和无障碍语义。
- 只有用户明确要求自定义菜单，或原生菜单确实无法承载需求时，才允许例外；例外实现前应说明原因。
