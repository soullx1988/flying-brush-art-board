# 外观与称号的收录与刷新

道具价值投放总览继续使用同一份 `itemValueOverview`。商品与历史从原商品总览引用，图标使用共用的 `evidence.icons` 和内容寻址资源；不另建商品清单。

`scripts/build-item-value-data.py` 调用 `item-appearances.py`，额外读取：

- `tables_sysplayer_tbplayerfashion.json`：非默认头像框、聊天框、称号。使用当前导出表，不扫描废弃的道具别名或源表注释行。
- `tables_sysheros_tbheroskins.json`：可见英雄、角色、武器皮肤。按皮肤类型与当前解锁道具定位，排除默认、隐藏与旧别名。
- `tables_syscommands_tbcommand.json` 及活动、竞技场奖励表：获得入口和奖励引用。均标明为配置线索，不据此宣称已上线或已领取。

同一外观的消耗道具、解锁后道具合为一项，`appearance.itemIds` 保留关联。没有背包道具的外观使用配置 ID，并明确标注身份；商品查找只使用真实道具 ID。

基础价仍直接读取《商业化产出》道具定价页。外观没有定价时保持 `null`，在主图末尾的“无定价”档显示；不会折算为零，不强制提出待确认问题。其他身份不明或缺价的资源仍留在定价待处理页。头像框、聊天框、称号等按类型合并，用三个图标与省略号展开。

刷新步骤：核对 SVN 版本并取得最新源表，运行原有构建脚本，再从“更新数值资料”导入。已有用户确认价由导入器保留。`coverageNotes` 保存人工核验事项，常规刷新未提供该字段时继续保留。

新增图标使用 `scripts/commerce/build-evidence.py` 的 `item_icons`；无道具行时可读取外观图标，图集外图标回退到游戏原始 PNG。向原商品总览导入资料包时，保留已有历史数据及全部被引用的图片文件。

验收重点：无定价外观可见且不混入零价档；分组展开不会丢失身份；关联别名不会重复计算商品；侧栏显示描述、期限、属性加成提示与出处。没有流水不能写成零销量，配置存在不能写成实际开放。
