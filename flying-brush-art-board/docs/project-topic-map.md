# 主题地图与局部关系图

项目首页以主题地图作为阅读入口，原来的全部画板列表保留在“画板”页签。主题只保存名称、简短说明和画板的主要归属；画板名称、正文、跨画板引用仍读取原对象。

## 使用

- 点击主题，再点击下一层画板名称，逐层展开。每个节点的“打开”直接进入原画板。
- 搜索同时匹配画板名称和完整所属路径。新建但尚未归类的画板显示在“待归类”，不会消失。
- 内容页顶部显示所在位置，“主题地图与关系”打开以当前画板为中心的视图，可以返回上级、切换同级或查看资源关联。
- “调整归属”改变一处主要归属；不会复制内容或改写画板内的引用。画板改名时地图与路径直接读取新名字。
- 局部图的箭头是已有引用的方向。没有把普通链接推断成“依赖”“验证通过”等设计语义。相同方向、相同目标的多处引用合并显示数量。
- “编辑主题”保存到项目共享数据。并发修改采用版本检查，旧版本保存会被拒绝，不覆盖别人的修改。

## 数据与维护

`projects.navigation_json` 保存 `ProjectNavigation`，包含主题和 `boardId -> parentId`。身份基于稳定 ID，不依赖标题编号。主题图、面包屑、搜索路径、画板顶部位置均从这份结构计算。局部关系读取 `BoardReferenceRecord`，没有另存一份边。

现有设计总纲的首次归类是一次迁移，之后不再运行按编号猜测归属的脚本。后续在应用内调整归属即可，不需同步维护静态目录、JSON 配置或另一张关系画板。

后端验证主要归属不成环、不跨项目、不指向缺失画板。删除允许删除的画板时，其直属下级继承原上级；没有原上级时进入待归类。原有引用保护和默认画板删除保护继续生效。

`.iboard` 项目包的可选 `navigation` 字段保留结构；合并导入时重新映射画板及主题 ID，保留目标项目已有主题。无该字段的旧包仍能导入。带主题的新包需要支持此可选字段的应用版本；旧版严格解析器不会认识它。

## 验证

核心模型、API、地图界面与项目包均有测试覆盖。验收包含逐层导航、局部引用图、搜索路径、主题说明保存与刷新、并发版本检查，以及项目包导出、预检、重新映射和隔离数据库导入。

真实项目的归类脚本、数据库备份和验收截图属于本地资料，不放入代码仓库。导出项目包可以搬运画板及其主题结构；生产数据仍由应用的数据目录和备份流程维护。
