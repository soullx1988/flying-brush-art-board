# 道具价值投放总览

独立画板通过 `document.meta.itemValueOverview` 识别。它不修改商业模式总览，也不复制商品售价、折扣或历史流水。

## 数据归属

- 道具基础价由用户指定的数值表负责，单位为每个道具的钻石基础价值。必须保留文件、工作表、单元格或字段依据。缺价用 `null`，不得按零元、旧草案或商品成交价补齐。
- 《商业化产出》目前没有独立基础价列。对“日周月礼包表”“日周月礼包”中的单品行按 `钻石价格 × 返利比 ÷ 数量` 还原；只填折扣时为 `价格 ÷ 折扣 ÷ 数量`。这些条目标记“表内推算”，不是已确认精确定价。保留各行还原值的最小/最大值；中位数只用于布局排序，不作为精确价展示。返利比本身的舍入误差未知，范围不是统计置信区间。
- 同名必须在配置中唯一匹配，不擅自映射旧名。重复工作表的相同关系去重；还原值相差超过 15% 时暂不入图，保留冲突明细。链式礼包总价值、免费/广告商品、缺返利关系或损坏公式的行不拆算为道具基础价。钻石 1:1 只是坐标单位。
- 投放来自工程配置。目前提取主线奖励、功能开启奖励及部分商品入口条件；入口开放不等于道具已获得。未覆盖的引导、邮件、任务和后台活动继续标记待核验。
- 道具身份使用 item ID。图标、关联商品和历史入口实时引用 `sourceBoardId` 对应的商品总览；画布节点只保存 item ID。
- 图中纵向为明确标注的价格区间，横向为进度阶段。活动、个性化条件和未知位置单列，不能解释为同一时间轴上的先后顺序。

## 更新

1. 从源商品画板导出快照，读取同版本工程配置。
2. 对本次指定文件，直接运行 `python scripts/build-item-value-data.py --catalog <snapshot.json> --config-dir <Datas> --source-board <boardId> --commercial-workbook <商业化产出.xlsx> --audit-output <audit.json> --output <data.json>`，不维护第二份手填价格表。需要 Python 的 openpyxl，只读打开原表。
3. 其他已确认的基础定价表也可生成临时读取结果：`{ "道具ID": { "value": 数值, "source": "文件/工作表/单元格", "note": "可选说明" } }`，改用 `--prices <price-readout.json>`；两个定价入口不能同时使用。原表、生成结果和审计明细保存在本地私有资料目录，不提交项目仓库。
4. 新建画板时执行 `tsx scripts/package-item-value-map.mts <data.json> <output.iboard>`，通过“导入文件”正常合并到现有项目。后续使用该画板的“更新数值资料”读取生成结果，避免重复新建。导入目标项目必须能够访问原商品画板及其图标资源。

“刷新商品引用”只重读商品、图标和历史入口，不改变数值来源。“整理坐标”或更新资料会重排自动生成的道具和坐标，保留手写说明、批注和其他页面；支持画板撤销。自由拖动不改变基础价或投放配置。

导入项目包会重编记录 ID，因此页面按 `itemValuePage` 标记定位，道具按 `itemValueNode.itemId` 定位，不能依赖初始记录 ID。
