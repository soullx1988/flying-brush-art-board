# 道具价值投放总览

独立画板通过 `document.meta.itemValueOverview` 识别，不修改商业模式总览。商品售价、折扣、图标和历史流水仍引用原商品总览。

## 唯一取值口径

- 读取现用数值项目 `重构版_20260822/outputs/商业化产出.xlsx` 的 `IN_玩法_道具定价` 页，按 F 列道具 ID 对应 D 列“钻石价值”。这页是上游 `玩法产出.xlsx/道具定价` 的输入快照，不在画板另行定价。
- 2026-10-29 已逐单元格核对这两个页的 A:G，快照与上游一致。来源固定记录 SVN 导出版本、文件 SHA-256 和价格单元格；刷新时重新导出正式表并读取，禁止继续使用设计总纲目录中的旧同名副本。
- 缺定价页或表头不匹配时直接报源文件错误。绝不降级到礼包售价、返利比、折扣、旧价格草案或历史成交价反推。
- 公式读取源工作簿保存的结果，不自行构造公式。空白、错误、未计算公式和重复 ID 不同价保留具体缺项，不能归零或取平均。
- 道具 ID 优先。缺 ID 的源行仅允许与唯一同名工程道具匹配。有不同 ID 时不能因同名串价。碎片经工程 `debris=1` 核对后显示全称；其余同 ID 名称差异保留说明。
- 源表明填零与缺价不同。零只表示表内定价值，不表示商品免费。旧版反推的 `priceEstimate` 数据读取时自动停用，不再显示区间或中位数。
- 各项展示单一基础值。纵轴价格档只是分层方式。商品具体折扣仍在商品总览维护。

## 投放与引用

投放来自工程配置，目前覆盖主线奖励、功能开启奖励和部分商品入口条件。入口开放不等于已获得道具；未扫描完整的引导、邮件、任务、后台活动不能标成全游戏首次。

画布节点只保存 item ID。图标和关联商品由 `sourceBoardId` 动态读取；定位道具、展开详情、关联商品入口沿用现有控件。

## 更新

只读提取脚本：`scripts/build-item-value-data.py`。传入 `--catalog`、`--config-dir`、`--source-board`、`--commercial-workbook`、`--output`；SVN 来源同时传入 `--commercial-source-url`、`--commercial-source-revision`，用 `--audit-output` 保留核对报告。

在原画板“更新数值资料”导入结果，再点“二维总览”。更新保留原道具节点身份、批注连线和其他自由内容，仅重建自动布局。数据 JSON 是生成物，不要求策划额外维护一份。

## 当前范围与核验

当前收录 149 项：128 项直接读取源表价值，18 项部位宝石采用下述用户确认价，3 项保留缺价（当天免广告卡、入矿凭证、尚未在本地道具配置识别的 6001001）。未经确认不能将随机宝石定价套用到部位宝石。另有一个同 ID 的英雄碎片名称差异，价格照源表读取，名称差异保留。

2026-10-29 后续确认：精良／稀有／史诗各 6 个部位宝石分别统一 40／160／640 钻。18 项在原画板数据中保存 `approvedPrice` 及用户确认来源，当前共 146 项已定价，剩余 3 项缺价和 1 项名称核对。正式表尚未收录的确认值会在后续导入时保留；源表补齐相同值后显示源表出处，不同值保留明确差异说明，避免旧资料清空已确认结论。

同类视图按工程道具类型、碎片标志、品质、相同单价及投放分区自动分组。至少 2 项才收束，货币和通用材料不按名称猜测合并。组卡最多显示 3 个现有图标、其余省略号、总数量及单个基础价；展开恢复原来的独立道具节点，保持 ID、批注和引用。展开/收起仅重排自动布局并保留手动位移，不创建第二份商品或定价明细。“定位同类”定位组卡，“定位道具”可自动展开所属组。

确认前的复核按 SVN r52745 导出正式表并核对上游，将当时的 21 个缺价道具归纳成 6 项定价事项和 1 项名称核对。随机宝石与部位宝石的关系由工程掉落池生成；当时 40／160／640 钻仅作为参考，直到用户明确确认才应用到 18 项部位宝石。清单随已确认价格自动扣除已处理事项。

`reviewGroups` 是提取脚本生成的核对结果，不是第二份定价表。正式表后续维护时，应将用户确认的补充定价写入权威上游并刷新输入快照；仅改变画板说明文字不会改变基础价。当前已确认结论由结构化的 `approvedPrice` 留存，未经用户确认不得自动产生该字段。

自动验证覆盖直接列读取、拒绝旧副本及售价反推、空白/错误/零、重复 ID 冲突、碎片和本体区分、名称差异、旧估算停用、节点身份保留、图标和商品引用。浏览器验收检查固定值、来源、缺项、保存后重载与商业总览不变。
